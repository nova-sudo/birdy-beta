Admin pages

Paper only has a generic "Table" for these screens. Here is how all six admin pages look on the new kit: the admin shell from Task 10, each page header as a PageHeader, every table as a DataTable, every stat row as a MetricGroup, and every chart in a Surface. The copy, endpoints, dialogs and safety checks stay the same. One decision is yours: the row actions on Agencies (section 1). Everything else is a straight port.

1 · Agencies (/admin, which redirects here)

The page has a MetricGroup of 5 platform KPIs above a DataTable with search, sorting by any number column, and pagination. Each row currently has four inline buttons (Chats, Limit, Impersonate, Delete). Pick how they show:

A · Primary action + "more" menu Recommended

Impersonate stays a visible button. Chats, Client limit and Delete move into a ⋯ menu, with Delete last and in red. The rows stay one line at 1280px, and Delete is harder to hit by mistake. Every action still opens its existing confirm dialog.

6 · Shared pieces

  • Shell: the AdminShell already uses the ds sidebar (Task 10). It stays as is: Admin title, "Staff only" warning Badge, "Back to app".
  • Dialogs: Impersonate, Delete (type the email to confirm), Client limit, Grant credits and Create promo move to the ds Dialog and AlertDialog, with the same copy and guards. Delete keeps its typed-email check.
  • Loading and empty states: DataTableSkeleton while loading, EmptyState for "no matches", and ErrorState with retry if a request fails.
  • Below md: the shell's mobile sheet takes over, MetricGroups wrap to 2 columns, and tables scroll sideways inside their own frame (the page never scrolls sideways).
